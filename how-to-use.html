VisualEdit

How to use VisualEdit

Edit your local website visually in Chrome. Every change is written into your project files.

What you need

  • Google Chrome with the VisualEdit extension.
  • Node.js, the current LTS version (20.12 is the minimum). Install it once; most developers already have it.
  • A website project on your computer that you open on localhost: plain HTML and CSS, or React with Vite (Tailwind CSS v4 or plain CSS). Other frameworks are not supported yet (see below).

The steps below were tested on Windows with Chrome. The side panel shows the same steps when the helper is not running: pick your kind of project there and it ticks each step as it is done.

Step 1: open a terminal in your project folder

The terminal must be opened in your site's folder (the one with index.html, or with package.json). A new terminal usually starts in your home folder, which is not your project.

  • File Explorer: open your folder, click the address bar, type powershell and press Enter.
  • VS Code: File > Open Folder, then Terminal > New Terminal. It opens in your folder.
  • Already in a terminal: type cd, a space, drag your folder into the window and press Enter.

The line must end with your folder's name, for example PS C:\Users\you\Desktop\my-site>.

Step 2: start the helper

In that terminal run:

npx visualedit-agent

If it asks Ok to proceed? (y), type y and press Enter. You should see VisualEdit agent is running and a Project: line. The Project: line must show your folder. Keep this window open while you edit. If you start it in your home folder, the top of a drive or a system folder, it does not start and tells you to open a terminal in your site's folder.

Step 3: start your site

Your site needs a server, so you have a second program running next to the helper.

Plain HTML and CSS

  • VS Code with Live Server: open your folder and press Go Live at the bottom right. Your site opens in a new Chrome tab. No Go Live button? Install the "Live Server" extension in VS Code. No second terminal is needed.
  • No VS Code: open a second terminal in the same folder (step 1) and run npx http-server -a 127.0.0.1 -c-1. Then open http://localhost:8080 in Chrome. (-a 127.0.0.1 keeps your site on your own computer, -c-1 stops the browser from keeping old copies.)
  • Python installed: py -m http.server 8000 --bind 127.0.0.1, then open http://localhost:8000.

React with Vite

In a second terminal in the same folder: the first time only run npm install (it can take a few minutes), then npm run dev. The terminal prints an address, usually http://localhost:5173. Open it in Chrome.

Not supported yet

Next.js, Nuxt, Astro, Gatsby, Remix, Angular, Svelte and Vue projects are not supported yet. If you start the helper in one, it says so and does not change any file. Tell us which framework you use at the address under Help: it helps us decide what to add next.

Step 4: edit

  1. Open the side panel. Click the VisualEdit icon in Chrome's toolbar while your site is open in the tab. The first time, read the short notice, tick the box to agree to the Terms and the Privacy Policy, and press I understand. The panel shows a green dot and your project's name when the helper is running.
  2. Select an element. Turn on Select at the top of the panel and click anything on your page.
  3. Change it.
    • Properties: change colours, sizes, spacing, fonts, borders and more by hand, then press Save. Unlimited and free.
    • Chat: describe the change in plain words, for example "make this button green and a little bigger". The AI writes it for you.
    • Tree: see the structure of your page and pick the exact element you want.
    • The tools row (the chevron next to the tag name) moves, duplicates, adds and deletes the element.
  4. See the result. The change is written into your files right away and your page updates.
  5. When you are done, press Ctrl+C in each terminal to stop the helper and your site.

Undo and safety

  • Undo and Redo at the top of the panel step through your changes. Revert all puts every file back as it was when you started the helper.
  • Git is not required. If your project is a git repository, VisualEdit also commits each change (the message starts with VisualEdit:), so you can review or undo it later with your usual git tools.
  • For an important project, keep a copy or use git, as you would with any tool that writes your files.

Git (optional, recommended)

Git is a free tool that keeps a history of your project. You do not need it to use VisualEdit, but with it every change can be reviewed and taken back at any time, even after VisualEdit is closed.

If your project is already in git: VisualEdit saves each change as its own commit, with a message that starts with VisualEdit:. It only commits the files it wrote, so your own unfinished work is left alone. See what it did with git log. Take one change back with git revert <commit>.

If your project is not in git yet, to start using it:

  1. Install git once (on Windows, the installer's default choices are fine). Check it with git --version in a terminal.
  2. Tell git who you are, once: git config --global user.name "Your Name" and git config --global user.email "you@example.com".
  3. In your project folder run: git init, then git add ., then git commit -m "First version". This saves your project as it is now, before any VisualEdit change.
  4. Restart the helper (npx visualedit-agent) in that folder. The panel now tells you the project uses git.

To keep a copy online (optional): create a free account on GitHub, create a new empty repository there (private if you like), and GitHub shows two commands to copy: git remote add origin <the address> and git push -u origin main. Run them in your project folder. After that, send your changes any time with git push.

If you do not want any commits from VisualEdit, simply do not use git in that folder: Undo and Revert all keep working without it.

If something does not work

  • "Agent offline": the helper is not running. Do step 2 again; the panel finds it within a few seconds.
  • npx or node is "not recognized": Node.js is not installed yet. Install the LTS version from nodejs.org, then close the terminal and open it again.
  • The helper refuses to start ("is your home folder, not a project folder"): the terminal was opened in the wrong place. Open it in your site's folder (step 1) and run the command again.
  • The Project: line shows another folder: press Ctrl+C, open a terminal in your project's folder and start the helper again.
  • "The agent is connected. Open your site on localhost...": the tab in front is not a site on localhost. Open your site in that tab (step 3), or press Check again.
  • "This page is open, but its server is not running": your site was stopped. Start it again (step 3) and press Check again.
  • "This page is not from the agent's project" or "out of date after recent edits": the site in the tab and the helper belong to different projects. Check that both were started in the same folder.
  • "This project is not supported yet": the helper found a framework it cannot edit (see step 3). Nothing was changed.
  • A certificate error when you run npx visualedit-agent (the message mentions certificate or UNABLE_TO_VERIFY_LEAF_SIGNATURE): this is common with antivirus, VPN or office networks. In PowerShell run $env:NODE_OPTIONS="--use-system-ca"; in Git Bash, macOS or Linux run export NODE_OPTIONS=--use-system-ca. Then run npx visualedit-agent again in the same window. This needs Node.js 22.15 or newer; with an older Node.js, install the current LTS first.
  • EADDRINUSE or "address already in use": another server is still running on that port, often an old terminal window. Close it with Ctrl+C, or start your site on another port, for example npx http-server -a 127.0.0.1 -p 8081 -c-1.
  • The file changed but the page still looks the same: the browser is showing an old copy of your CSS. Press Ctrl+Shift+R on the page. If you use http-server, start it with -c-1 so it never asks the browser to keep old copies.
  • "Element not found in the source file": the page is out of date or comes from another folder. Reload the page and select the element again.
  • "No existing :hover rule found": the Hover tab edits an existing :hover rule. Add one to your stylesheet first, for example .button:hover { }.
  • The AI did not change what you expected: the AI changes only the selected element. Select the right one (the Tree tab helps) and describe the change again.
  • "You've used all your free AI requests": editing by hand in Properties stays free and unlimited. Get Pro under the chat box shows the plans.
  • "The free AI is at capacity right now": try again later. Editing by hand still works.

Privacy

The extension only works on localhost pages. Only an AI command sends something out: your command and the code of the selected element. Read the Privacy Policy.
